# InfoChord Constitution

## Core Principles

### I. Evidence Before Claims
Describe only behavior supported by source, repeatable checks, or clearly labeled manual observations. Call InfoChord a prototype unless production readiness is independently demonstrated.

### II. Safe, Explicit Mutations
Any UI action that changes or deletes stored documents must be triggered by an explicit user action; page rendering must never mutate data. Make destructive actions clearly labeled and confirmed.

### III. Preserve Distributed-System Boundaries
Keep Chord membership, node storage/replication, query coordination, and client/UI responsibilities understandable and separately documented. Avoid implying guarantees not validated under node failures or concurrent changes.

### IV. Reproducibility Over Convenience
Document exact prerequisites, configuration, and commands. Verify what can be run; disclose infrastructure-dependent checks that could not be executed.

### V. Minimize Exposure and Noise
Never commit secrets, personal data, local environments, or generated bytecode as part of a showcase. Keep configuration examples safe and separate from local overrides.

## Quality Bar

- Add or update automated tests when a behavior can be isolated; otherwise document a concrete manual smoke check.
- Run syntax and configuration checks after changes. State clearly when Docker/runtime checks are blocked by unavailable infrastructure.
- Keep demo data disposable and do not expose a live embedding endpoint or private documents.

## Showcase Bar

- The README and architecture notes are in English, with the existing Spanish UI allowed to remain.
- Explain the system as a prototype for distributed semantic document search; distinguish implemented features from verified reliability.
- A reviewer should be able to identify the topology, data flow, configuration, startup path, test limitations, and safe demo workflow.

## Governance
This constitution governs project specifications and showcase documentation. Amendments should be explicit and must not silently weaken safety, evidence, or reproducibility requirements.
